# Architecture

Patty is a loopback-only, single-user daemon. SQLite WAL stores local API-key hashes, opaque account aliases, model/quota snapshots, thread affinity, run metadata, short selection leases, active capacity, per-run token counts, and content-free audit metadata. It does not store prompts, outputs, identities, OAuth tokens, refresh tokens, cookies, or Codex auth files.

A short transactional routing lease prevents simultaneous selection. It is converted atomically to `active_runs` and released before execution; terminal handling atomically decrements active capacity once. Runs persist provider turn IDs, so cancellation uses the documented provider turn identifier rather than Patty's local run ID. The SSE stream provides bounded retained events, sequence IDs, heartbeats, terminal close, and 404 before a stream is opened for an unknown run.

Provider text is still never persisted, but a subscriber that opens the SSE stream after the turn already produced output would otherwise see only redacted markers. The coordinator keeps the current turn's text in a bounded in-process buffer (64 KiB, dropped 60s after the run is terminal) and the stream substitutes it for the first replayed `delta`. A reasoning model's thinking is carried the same way — its own `reasoning` event, its own buffer of the same size and lifetime, persisted as the same redacted marker, and substituted for the first replayed `reasoning` row — and `PATTY_FORWARD_REASONING=0` drops it before any of that happens. Removed subs keep their rows so their usage history survives, and are filtered out of `/v1/accounts`, `/v1/router/status`, and `/v1/models`.

The loopback console is one static document served from the daemon at `/`; it holds no server state and reads every value through the same authenticated JSON API a CLI user would call, so the operator's `cp_live` key stays in the browser only.

A sub is considered logged in when `account/read` returns an `account`. The companion `requiresOpenaiAuth` flag is not a readiness signal: a genuinely signed-in ChatGPT account on 0.145.0 reports it as `true`. Because a sub's login lives in its isolated `CODEX_HOME` rather than in the daemon, the daemon re-attaches an app-server worker to every stored sub whose home still exists at startup (`restoreCodexAccounts`) and reports the aliases it recovered; without that a restart would strand logged-in subs in `reconnect_required` with no worker to refresh.

One narrow exception to "Patty never touches a sub's auth file": lending a subscription. A caller that runs Codex itself cannot be served an answer, so `credential()` asks the app-server to refresh (`account/read {refreshToken:true}`) and then reads the resulting access token and account id out of that sub's own `auth.json` — the app-server has no RPC that hands a token back. The refresh token is never read, the access token is never written anywhere, and nothing in the lease tables or logs contains credential material; a lease row holds only who has which sub until when.

The real `CodexAppServerAdapter` verifies the configured command (`PATTY_CODEX_COMMAND`, or `codex` on PATH) reports a `codex-cli` version inside the supported range (`SUPPORTED_CODEX_VERSIONS`: `>=0.145.0 <0.148.0`) before starting; `PATTY_CODEX_VERSION=<version>` names one exact release beyond it that the operator has verified. An exact pin was worse than the drift it guarded against: a routine `codex upgrade` on the box moved every logged-in sub to `reconnect_required` with no failover, since a lease can only come from a Codex login. `doctor` therefore reports a present-but-unspeakable CLI as ill health, and a restore failure logs `sub_restore_failed` with the reason. It then uses the official `initialize`/`initialized` handshake, isolated `CODEX_HOME`, JSONL stdio RPC, bounded pending request timeouts, redacted stderr, and explicit child shutdown. Contract coverage is generated from official 0.145.0 shapes. The live path has been exercised by an operator against two of their own ChatGPT subscriptions — login, snapshot, restart restore, streamed turns, and provider-reported token counts.
